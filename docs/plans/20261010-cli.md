# Ollama-like CLI

Roadmap phase 7: a pleasant `wavo` command on top of the finished engine, without changing the
engine or the library API.

## Goal

```
wavo pull parakeet-v3                # download a model by short name
wavo list                            # downloaded models
wavo rm parakeet-v3                  # delete one
wavo run parakeet-v3 talk.m4a        # transcribe; plain text; never downloads
wavo run talk.m4a                    # default model parakeet-v3
wavo run parakeet-v3 talk.m4a --json # or --srt
wavo bench MODEL AUDIO [-n N]        # as before
```

Only `pull` touches the network. `cargo add wavo --no-default-features` still gets a pure Rust
library with its current API. Fixtures stay exact, also through `wavo run` on the fixture WAVs. The
CLI stays within ~700 lines, counted apart from core + family.

## Design

- **One crate, `cli` feature.** `default = ["cli"]`; `cli` enables the optional `anyhow`, `ureq`,
  `symphonia` and `rubato`. The binary `wavo` is `src/cli/main.rs` with
  `required-features = ["cli"]`, plus a few modules (registry and cache, audio, output). `hound`
  becomes a dev-dependency (`tests/models.rs`). `make check` adds clippy with
  `--no-default-features`.
- **Registry.** One table: name, published variant, Q8_0 size from
  `3rd/transcribe.cpp/catalog/<variant>.json`, a few words of description. Names: `parakeet-v3`,
  `parakeet-v2`, `gigaam-v3` (= `gigaam-v3-e2e-rnnt`), and the full names for the other GigaAM
  variants (`gigaam-v3-e2e-ctc`, `gigaam-v3-rnnt`, `gigaam-v3-ctc`): a shorter `gigaam-v3-ctc` for
  e2e-ctc would collide with the charwise CTC model's full name. Full names are accepted
  everywhere. An argument ending in `.gguf` or containing a path separator is a local file. An
  unknown name fails with the known names and the closest one (edit distance), without network.
- **Cache = the Hub local cache spec** (https://huggingface.co/docs/hub/local-cache, also used by
  `hf` and llama.cpp; cited in the code), our own module of ≤ ~200 lines with the download. Root
  as Python huggingface_hub resolves it: `HF_HUB_CACHE` (legacy `HUGGINGFACE_HUB_CACHE`), else
  `$HF_HOME/hub`, else `${XDG_CACHE_HOME:-~/.cache}/huggingface/hub` (`USERPROFILE` when `HOME`
  is unset). Repo folder `models--handy-computer--<variant>-gguf` with `blobs/<sha256 etag>`,
  `snapshots/<commit>/<file>` → `../../blobs/<etag>`, `refs/main` = 40-hex commit. Lookup: the
  snapshot named by `refs/main`, else any snapshot that has the file; symlinks are just followed
  (newer `hf` points `blobs/<etag>` further into a shared `<root>/blobs/<xx>/<xet hash>` store).
- **`pull`** (as huggingface_hub's `_hf_hub_download_to_cache_dir`): HEAD
  `${HF_ENDPOINT:-https://huggingface.co}/handy-computer/<variant>-gguf/resolve/main/<file>`
  without redirects, `Accept-Encoding: identity`; commit from `X-Repo-Commit`, etag from
  `X-Linked-Etag` or `ETag` (quotes and `W/` stripped), size from `X-Linked-Size`, download URL
  from `Location`. Snapshot file present: only refresh `refs/main`. Else take the lock
  `<root>/.locks/<repo folder>/<etag>.lock` (`File::lock`); `blobs/<etag>` present: only link it;
  else download to `blobs/<etag>.incomplete` (resumed with a `Range` request after an interrupted
  pull; `hf cache prune` cleans it), check the size, rename to `blobs/<etag>`. Then the relative
  symlink; where symlinks fail (Windows without developer mode) the file itself moves into
  `snapshots/` and `blobs/` stays unused, as the spec's degraded mode. Last, `refs/main` via a
  temp file and rename. Progress on stderr: one updating line on a terminal, start and end lines
  otherwise.
- **`rm`** touches only our file inside the repo folder: it removes `<file>` from every snapshot,
  the blobs those entries pointed to, snapshot dirs left empty and the refs naming them, and the
  repo folder once no snapshot is left (other quants downloaded with `hf` stay). When the blob is a
  symlink into `hf`'s shared store it deletes nothing and prints
  `hf cache rm hf://models/handy-computer/<variant>-gguf/<file>` instead.
- **`list`**: downloaded registry models with size and path.
- **Only `pull` uses the network.** `run` and `bench` never download, the default model
  included. A missing model fails with the exact command:
  `parakeet-v3 is not downloaded; run: wavo pull parakeet-v3 (0.74 GB)`. `wavo run X` where X is
  a model name and not a file reports the missing AUDIO.
- **HTTP:** `ureq` 3 with `rustls` only (ring + webpki roots; no gzip, model files are not
  compressed). No tokio, curl or hf-hub: hf-hub 1.0 is async-only (tokio, reqwest with aws-lc,
  hf-xet) and took the CLI from 67 to 269 crates, its clean build from 35 to 110 s and the
  stripped binary from 5.6 to 15.9 MB; `ureq` takes it to 85 crates, 39 s and 7.4 MB.
- **Audio:** `symphonia` 0.6 with `wav`, `pcm`, `mp3`, `isomp4`, `aac`, `flac`, `ogg`, `vorbis`
  (no Opus: symphonia has no decoder). Channels averaged to mono; `rubato` 5 FFT resampler to
  16 kHz only when the rate differs, so a 16 kHz mono WAV gives exactly the samples `hound` gave.
- **Output:** plain text by default. `--json`: `{"text": ..., "tokens": [{"id", "piece",
  "start_ms"}, ...]}`, one token per line, hand-escaped. `--srt`: words from pieces (`▁` or a space
  piece starts a word), a cue ends after sentence punctuation (`.`, `!`, `?`, `…`) or before
  exceeding 80 characters; a cue lasts until its last token's start + 1.5 s or the next cue's
  start (the audio end for the last cue), whichever is earlier, so it does not hang over silence;
  cue text detokenized like `Transcript::text`.
- **Long audio:** measure `wavo run` on a ~10-minute file for `gigaam-v3` and `parakeet-v3` (time
  and peak footprint) and log it in `docs/perf.md`; no chunking in this phase.
