# Neural Engine backend

Done: 2026-10-12, PR #37

A macOS backend that runs the encoder of the Conformer families (Parakeet, GigaAM) on the Apple
Neural Engine through Core ML; Whisper and Moonshine stay on the GPU, where the ANE was slower
([other engines](../20261010-other-engines.md)). A spike (2026-10-12) built Parakeet V3's encoder
from our Q8_0 GGUF as a Core ML ML Program and ran it 100% on the ANE through public APIs: 35 ms
(M2) / 41–44 ms (M1) per warm 15 s window against 154 / 209 ms on wavo's GPU.

## Decisions

- **Model source.** wavo writes the program itself, in Rust, from the GGUF: a hand-written
  protobuf encoder, a MIL graph builder and the `.mlpackage` writer (`src/ane/`), compiled with
  `MLModel.compileModelAtURL`. No Python, no published Core ML models, no new build tooling.
  Binding: `objc2-core-ml`, a macOS-only target dependency of the `objc2` family wgpu already uses.
- **Weights.** Q8_0 linear weights re-quantized to int8 with one F16 scale per output row (the ANE
  runs Q8_0's 32-wide blocks on the CPU only), other weights F16: one program of ~650 MB, which
  the M2 places on the ANE (it refuses programs over ~1 GiB).
- **Window.** One fixed 15 s shape: shorter audio is padded and masked; longer audio is split at
  pauses into pieces of the window.
- **Backend choice.** `Backend::Auto` by default in the library and the CLI: per family, the faster
  backend on this machine, kept as a table next to the families (`AUTO` in `src/lib.rs`). Parakeet
  and GigaAM use the ANE once prepared, else the GPU silently; Whisper and Moonshine the GPU.
  Explicit `Gpu` (exact, the fixture path) and `NeuralEngine` (an error when unavailable or not
  prepared). `Model::device()` tells which one runs: the Neural Engine is a `Device` of kind
  `NeuralEngine` (API `CoreMl`), which `wavo::devices()` lists last.
- **Prepare.** Never inside `load`: `Model::prepare(path, progress)` builds, compiles and loads
  once. The system caches its ANE compile (10–30 s) per program, so each program prepares for
  itself; a prepare in another program skips the build and only loads. `Auto` uses the ANE only
  in a program that has loaded the model there before (a marker per program next to the compiled
  model), so `load` never stalls. `Hub::pull` calls `prepare` after a download, `wavo pull` shows
  its steps. Compiled models live in `~/Library/Caches/wavo/`, outside the Hugging Face cache, as
  `<file stem>.<id>.v<graph>.mlmodelc`, the id a hash of the file's size, modification time and
  first and last MiB, so a new revision that changes only middle tensors still gets a new one.
  `prepare` deletes the other ids and graph versions of its stem (older revisions, or another
  file of the same name), so one compiled model is kept per model name, and those unused for 30
  days (GGUFs deleted elsewhere); `Model::unprepare`, `Hub::remove` and `wavo rm` delete a file's
  own. One cache-wide lock serializes prepare, prune and remove, so `rm` waits for a running
  prepare.
- **Long audio.** On the ANE `max_audio_ms()` is 15 000 and `transcribe` splits longer audio at
  pauses itself with `wavo::split` (#66), and `Model::transcribe_long` cuts pieces of that window.
- **Correctness** (approved 2026-10-24). The GPU keeps the exact fixtures, tested with
  `Backend::Gpu`. On the ANE (F16 activations, int8 weights, arithmetic that differs per chip
  generation), macOS-only agreement tests per clip: the words, case and punctuation aside, within
  max(1, 2%) word edits (a word split in two or two merged is no edit), at most one word differing
  only in punctuation or case, and at least 95% of the aligned word tokens starting within two
  encoder frames. A clip up to 15 s is held to the fixture, a longer one to the GPU's transcript of
  the same pieces. When ANE code or a model changes, a corpus check: ANE against GPU on an hour of
  speech cut at pauses (`make compare` with `BACKEND=ane` and `gpu`, `batch compare` of the two
  runs), a WER of at most 0.2% and
  the same text on at least 95% of the 2–15 s pieces.

## Result

Warm `wavo bench` medians, ms, 11 s `jfk` / 35.3 s `dots` (3 pieces on the ANE) / 4.5 s `ru`;
ANE against wavo's GPU and transcribe.cpp on Metal (M5 numbers from the orchestrator's run):

| Model | Mac | ANE | GPU | transcribe.cpp |
|---|---|---|---|---|
| parakeet-v3 | M1 | **70 / 250 / 53** | 252 / 643 / 115 | 295 / 968 / 142 |
| parakeet-v3 | M2 | **57 / 201 / 44** | 149 / 442 / 72 | 269 / 808 / 96 |
| parakeet-v3 | M5 | **43 / 151** / – | 95 / 302 / – | |
| gigaam-v3 | M1 | **52 / 178 / 42** | 170 / 430 / 70 | 180 / 523 / 74 |
| gigaam-v3 | M2 | **46 / 160 / 40** | 92 / 290 / 47 | 105 / 372 / 53 |
| gigaam-v3 | M5 | ru-long **93**, ru 27.1 | ru-long 162, ru 26.3 | |

A prepared load takes 60–150 ms, the process's peak footprint 16–21 MiB (the weights live in the
system's ANE service) against 315–780 MiB on the GPU. The first prepare takes 14.4 / 11.7 s on
the M2, 26.2 / 22.6 s on the M1 and 9.2 / 7.5 s on the M5 (Parakeet / GigaAM), almost all of it
the system's ANE compile; the compiled models take 680 / 254 MB. Agreement on the test clips: the
same words everywhere, at most 3 of 38 tokens a frame or two off on Parakeet and 4 of 148 one
frame off on GigaAM, one comma dropped on GigaAM `ru-short` on the M5. The clean library build
gains one crate (`objc2-core-ml`, 0.3 s); `objc2` and `objc2-foundation` were already there for
wgpu.

Rebased on 2026-10-22 and measured again on the M2 (macOS 27, other jobs running): warm medians
ANE / GPU, ms: Parakeet V3 61 / 151 on `jfk`, 46 / 73 on `ru`; GigaAM 51 / 92 on 11 s, 39 / 42 on
`ru`. First call after load 72 / 181 and 52 / 118. Energy per call on 11 s, the accelerator's own
power net of idle (macmon, 50 calls): Parakeet 0.23 J at ~3 W on the ANE against 1.37 J at ~9 W on
the GPU, GigaAM 0.15 J against 0.87 J. Peak footprint 25–60 MiB against 300–760 MiB. A cold
prepare takes 14.7 s (Parakeet: build 2.0, compile 0.2, ANE load 12.4) and 13.6 s (GigaAM) with a
peak of 1044 / 603 MiB; a new program pays the 11–13 s load again, then loads in 0.06–0.2 s.

Rebased on 2026-10-23 onto `wavo::split`, `wavo serve` and Parakeet Ultra, which runs on the ANE
as v3 does (its kestrel masking is the program's padding mask at one mel frame fewer). Agreement
with the GPU on the M2, on an hour of English read speech (LibriVox) cut at pauses: on 230 pieces
of 2–15 s, the same text on 97.4 / 95.7 / 97.0% of them and a word error rate of 0.067 / 0.050 /
0.000% (v3 / v2 / Ultra, case and punctuation aside); on 98 pieces of 25–60 s, which the ANE
splits at 15 s, 0.071 / 0.072 / 0.051% against the GPU at the same pieces, 0.8–2.5% against the
GPU in one pass (the cuts change punctuation and the words at them). The fixture clips up to 15 s
read exactly as their fixtures.
