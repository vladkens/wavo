# Linux

Roadmap phase 8, Linux part: wavo builds and runs on Linux through wgpu's Vulkan backend, matches
the fixtures there, and gets faster on GPUs without the Apple fast path. Follow `agents.md`; log
every measurement in `docs/perf.md` (baseline: "Linux: Intel N100").

## Goal

- `cargo install` works on Linux with only a linker, the Mesa Vulkan driver and access to the GPU
  (`render` group). `make check` and `make test` pass there; the fixtures stay exact.
- On an Intel N100 iGPU, a plain `cargo install` at least on par with transcribe.cpp's CPU build
  on every clip, load and peak memory included (now GigaAM is on par, Parakeet 1.2–1.8× slower,
  load 2–3× longer).
- The Apple fast path and its numbers stay as they are.

## What the N100 showed

- wgpu picks the iGPU (ANV) over llvmpipe. It has subgroups (8–32 lanes), SHADER_F16 and
  mappable buffers, but no cooperative matrices, so every kernel is the portable one.
- The encoder is 85–99% of the time. The reference's CPU encoder quantizes activations to Q8_0
  and multiplies in int8; that beats wavo's portable F32 kernels on this iGPU.
- The x86 fallbacks of `cpu::dot`, `tile` and `Q8::rows` don't vectorize well (`mul_add` without
  FMA is a libm call; `Q8::rows` dequantizes each row into a new `Vec`).
- Parakeet has a large fixed cost per call: 5.3 s of audio takes 2.1 s, 11 s takes 3.5 s.
- iGPU memory is flat per model (529 / 914 MiB): allocator blocks, not the arena.
- i915 cancels a GPU request 20 s after it was queued ("Fence expiration time out" in the kernel
  log), and wgpu still reports success: `poll` and `map_async` are `Ok`, no device-lost callback,
  no error.
