# Linux

Roadmap phase 8, Linux part: wavo builds and runs on Linux through wgpu's Vulkan backend, matches
the fixtures there, and gets faster on GPUs without the Apple fast path. Follow `agents.md`; log
every attempt in `docs/perf.md` and the benchmark numbers in Result below (the N100 baseline).

## Goal

- `cargo install` works on Linux with only a linker, the Mesa Vulkan driver and access to the GPU
  (`render` group). `make check` and `make test` pass there; the fixtures stay exact.
- On an Intel N100 iGPU, a plain `cargo install` at least on par with transcribe.cpp's CPU build
  on every clip, load and peak memory included (now GigaAM is on par, Parakeet 1.2–1.8× slower,
  load 2–3× longer).
- The Apple fast path and its numbers stay as they are.

## What the N100 showed

- wgpu picks the iGPU (ANV) over llvmpipe. It has subgroups (8–32 lanes), SHADER_F16 and
  mappable buffers, but no cooperative matrices, so every kernel is the portable one.
- The encoder is 85–99% of the time. The reference's CPU encoder quantizes activations to Q8_0
  and multiplies in int8; that beats wavo's portable F32 kernels on this iGPU.
- The x86 fallbacks of `cpu::dot`, `tile` and `Q8::rows` don't vectorize well (`mul_add` without
  FMA is a libm call; `Q8::rows` dequantizes each row into a new `Vec`).
- Parakeet has a large fixed cost per call: 5.3 s of audio takes 2.1 s, 11 s takes 3.5 s.
- iGPU memory is flat per model (529 / 914 MiB): allocator blocks, not the arena.
- i915 cancels a GPU request 20 s after it was queued ("Fence expiration time out" in the kernel
  log), and wgpu still reports success: `poll` and `map_async` are `Ok`, no device-lost callback,
  no error.

## Result

Intel N100 (4 cores, 24-EU UHD iGPU, 16 GiB, fanless), Ubuntu 24.04, Mesa 25.2.8: wavo on the
iGPU through ANV, portable kernels only. After the AVX2 decoder and the load change, wavo's
default build (`bench -n 10`) / transcribe.cpp 5bb2deb CPU build (`-march=native`, 4 threads, no
BLAS) / its Vulkan build (ggml-vulkan on ANV), ms (MiB for the peak: RSS plus iGPU buffers):

- Fixtures exact on ANV and llvmpipe. The reference's CPU build moves two tokens each on ru-long
  and jfk by 1–3 frames; its Vulkan build misses one comma on ru-short.
- The portable encoder is 85–99% of wavo's time (ru-long 7342, dots 11601 ms). The reference's CPU
  encoder multiplies Q8_0 activations in int8 (AVX-VNNI) and is faster on Parakeet; its Vulkan
  encoder beats wavo's from ru-short on (ru-long 6372, dots 8267 ms).
- Before the AVX2 decoder and the load change (first baseline): load 0.6 s GigaAM, 1.4 s
  Parakeet, iGPU buffers 529 / 914 MiB, the default build's decoder 145 / 419 / 1056 ms (GigaAM)
  and 343 / 2003 / 44 ms (Parakeet); now 10 / 24 / 55 and 64 / 236 / 6.5 ms.
- The reference's four CPU threads throttle after ~20 s on this fanless box (dots 8929 → ~11 000
  ms per call); wavo's iGPU stays at 750 MHz with the CPU idle.
- llvmpipe (native build, `-n 3`): ru 15.1 s, ru-short 41.2 s, jfk 61.9 s warm; load 6–19 s.
- Whisper large-v3-turbo, jfk: wavo 72.3 s warm, load 0.5 s, fixtures exact; reference CPU 41.8 s;
  the reference's Vulkan build is cancelled by i915 and prints "unlock the".
