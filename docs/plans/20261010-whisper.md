# Whisper large-v3-turbo

A third family, on the user's explicit request (`agents.md` → Scope): `whisper-large-v3-turbo`
first, then medium, large-v3, small and Breeze-ASR-25 as config. Follow `agents.md` → "Adding a
model"; read `docs/perf.md` before speed work.

## Goal

- `make test` reproduces the reference fixtures `jfk`, `zh-short`, `ru-long` and `jobs-silence`
  exactly: text, and every segment's start and text (see Fixtures). GigaAM and Parakeet fixtures
  stay exact.
- Against `transcribe-bench` on the same Q8_0 GGUF and WAV on the M2: warm, first call, load and
  peak footprint at least on par. Reference on the M2 (research's measurement): warm 1462 ms on
  `jfk`, 1730 ms on a 30 s clip.
- Weights stay Q8_0/F32 on the GPU as stored. The shared core plus `src/whisper/` stays within
  ~3k lines of Rust and WGSL, tests excluded (see Line budget).

- Frontend (`transcribe-mel.cpp`, `weights.cpp:448-456`): audio ≤ 30 s is zero-padded to 480 000
  samples before the mel (`model.cpp:1337`, `:1363-1371`); longer audio gets one mel over the
  whole clip. Reflect padding of 200 on both sides (`transcribe-mel.cpp:400-410`); frames =
  n / 160 + 1, the last dropped (`:742-747`). Per frame, all f32: x·window, the mixed-radix FFT 400
  (four radix-2 levels over 25-point naive DFTs, an f32 sin/cos table computed in f64;
  `:159-226`, `:305-318`, from whisper.cpp), power `re² + im²`; mel = f64 sum over the 201 bins
  in groups of 4 (`:520-533`), `log10(max(sum, 1e-10))` in f64 to f32 (`:535-538`); then the max
  over all emitted frames, floor max − 8, `(max(v, floor) + 4) / 4` in f64 to f32 (`:734-773`). The
  reference is clang on arm64 with FP contraction, so the power, the butterflies and the f64
  groups are fused multiply-adds: research matched only with explicit `mul_add`
  (`research:src/whisper/frontend.rs:146-234`; rustfft drifted, `research:VALIDATION.md:251`).
- Encoder (`encoder.cpp:178-303`): mel [3000][128] → conv1 k3 s1 p1 + bias + GELU → [3000][1280]
  → conv2 k3 s2 p1 + bias + GELU → [1500][1280] → + `pos_emb` → 32 pre-LN blocks `x +=
  out(attn(LN x))` (q, v, out with bias, k without; 20 heads × 64, scale 1/8, no mask), `x +=
  fc2(GELU(fc1(LN x)))` → final LN; LayerNorm eps 1e-5. GELU is exact-erf (`ggml_gelu_erf`,
  `encoder.cpp:143`, `:233`), on Metal `0.5·x·(1 + erf_approx(x/√2))` with Abramowitz–Stegun
  7.1.26 (`ggml/src/ggml-metal/kernels/unary.metal:103`, `common.h:103`). Always 1500 frames: an
  11 s clip runs the whole 30 s window.
- Decoder (`decoder.cpp:630-800`, `:809-900`): x = `token_embd[id]` + `pos_emb[pos]` (no scale,
  no norm); 4 pre-LN layers: causal self-attention over a KV cache, cross-attention whose K and V
  (`Wk·enc`, `Wv·enc + bv`) are computed once per window (`:595-615`), FFN; final LN; logits =
  `token_embd · x`, no bias. KV caches are F16 (`model.cpp:1999-2015`), flash attention is on
  (`:569-571`).
- Reference precision (only if a fixture mismatches): matmuls with M > 8 run `kernel_mul_mm`
  (both operands to f16), M = 1 `mul_mv` and M 2–8 `mul_mv_ext` (F32, no rounding)
  (`ggml-metal-ops.cpp:2442-2470`); flash attention rounds Q to f16 and reads F16 K/V
  (`fa.metal:328`, `:1284`).
- Decoding as `transcribe-cli` and `transcribe-bench` run it by default (no Whisper flags;
  `tools/transcribe-bench/main.cpp:367-369`):
  - Timestamps AUTO = segment-timestamp decoding: the prompt is [SOT, `<|lang|>`,
    `<|transcribe|>`] without `<|notimestamps|>` (`model.cpp:1425-1426`, `:1878-1891`,
    `examples/cli/cli.h:40`).
  - Language: detected once, on the first window, from SOT alone: argmax of the raw logits over
    the language ids, the first wins a tie (`model.cpp:1775-1827`); reused for later windows.
  - `no_speech_prob` = softmax of SOT's raw logits at `<|nospeech|>` = notimestamps − 1 = 50363;
    f32 `l − max`, f64 exp sums (`:1979`, `:2180-2200`).
  - Greedy at T = 0 over raw f32 logits, per step in this order: `suppress_tokens`;
    `begin_suppress_tokens` on the first generated token only; the timestamp rules
    (`:1026-1113`, HF's `WhisperTimeStampLogitsProcessor`: mask `<|notimestamps|>`; timestamps in
    pairs; monotonic; the first token a timestamp ≤ 1.0 s, i.e. ≤ 50365 + 50; if the logsumexp of
    the timestamps exceeds the best other logit, mask everything else); argmax with strict `>`
    (lowest id wins); logprob = best − (max + ln Σ exp(l − max)) with the sum in f64 (`:834-870`),
    averaged over the generated tokens (`:2212-2228`, `:2434-2444`).
  - A window stops at EOT, 256 generated tokens or 448 positions (`:1413`, `:2309-2323`).
  - Temperature fallback: ladder 0, 0.2 … 1.0 (`:1956-1962`). A tier is accepted when its
    compression ratio (miniz deflate of the ids as 2-byte LE, `:712-738`) ≤ 2.4 and avg_logprob
    ≥ −1. `no_speech_prob > 0.6 && avg_logprob < −1` stops the ladder and drops the window's
    output (`:2475-2515`). Hot tiers sample with `std::mt19937` seeded from `std::random_device`
    (`:1574`): a window that falls back is nondeterministic in the reference itself.
  - No previous-window conditioning, no initial prompt, no beam search.
  - One seek loop for every length (`:1740-1760`, `:2540-2590`), with HF's `_retrieve_segment`
    (`:1128-1260`): segments split at consecutive timestamps; seek moves to the last closed
    timestamp × 2 frames, or a full window when there are no pairs, the output ends in a single
    timestamp, or the no-speech skip fired. A short clip ending in `<|t|><|t|>` is decoded again
    from t. Long-form windows are 3000-frame slices of the whole mel from `seek`, zero-padded in
    mel space (`:1754-1758`). Segment times are window offset + (ts − 50365) × 20 ms; segment text
    is the decoded text ids, ASCII-trimmed; empty segments are dropped.
  - Text = one decode of all accepted text ids (< 50257, all windows), ASCII-trimmed
    (`:1514-1531`, `:1915-1920`). An unfinished tail that the next window decodes again is in the
    text twice but in no segment (`:2567`).
  - `max_audio_ms` is 0: unbounded, chunked internally (`docs/input-limits.md:56-62`).
- CLI output: `--timestamps token` is rejected for Whisper before it runs
  (`capabilities.cpp:18-21`, `transcribe-asr.cpp:121-126`), so `make fixtures` as is writes empty
  files. `--timestamps segment` decodes as the default AUTO and prints `text: …`,
  `detected-language: xx`, `segments: N` and `  [%7.2f -> %7.2f] text` lines
  (`examples/cli/asr.cpp:869-908`); no token lines.
- Tokenizer: GPT-2 byte-level BPE. Decoding maps each character of a vocabulary string through
  the inverse of `bytes_to_unicode` and concatenates the bytes (`transcribe-tokenizer.cpp:247-275`;
  invalid UTF-8 passes through raw). Ids: EOT 50257, SOT 50258, languages 50259–50358, translate
  50359, transcribe 50360, startoflm 50361, startofprev 50362, nospeech 50363, notimestamps
  50364, timestamps 50365–51865 (0.00–30.00 s); 50256 is an empty piece.
- Later variants: medium, small, large-v2 and Breeze-ASR-25 have 80 mels (conv1 K = 240, not a
  multiple of 32: pad to 256 at load) and vocab 51865 (special ids shift by one from translate
  on: read them from metadata and the vocab, never hardcode); large-v3 has 32 decoder layers;
  Breeze-ASR-25 is a large-v2 fine-tune with F16 conv weights, published as
  `handy-computer/Breeze-ASR-25-gguf`. head_dim is 64 in all.

## Design

### Shared and new

- Core, extended:
  - GEMM (both): `Epilogue::Gelu` (erf as ggml-metal's `erf_approx`, so outputs match its
    rounding), and GELU added onto x, pre-filled with `pos_emb` by a buffer copy before the pass,
    for conv2. W stays rounded to f16, as `kernel_mul_mm` does.
  - `im2col`: kernel size, stride and padding as params (GigaAM k5 s2 p2; Whisper k3 s1 p1 and
    k3 s2 p1).
  - LayerNorm: the portable kernel writes its 1024-float `row` only for rotary; d = 1280
    overruns it now.
  - Flash attention (head_dim ≤ 64 path) over one `[q | k | v]` buffer (row stride 3·d), so one
    GEMM with biases `[b_q | 0 | b_v]` projects all three.
- Core, new in `src/gpu/` (the next encoder–decoder family reuses them):
  - `gemv`: `y = epilogue(W·x + b)` for one row, Q8_0/F16/F32 dequantized in registers, F32
    accumulation, W not rounded (as `mul_mv`), an output offset (a KV cache row). Portable with a
    workgroup reduction; a subgroup version only if it measures faster.
  - `decode_attention`: one query per head over n keys of an F16 K/V cache with a row stride, q
    rounded to f16, online softmax in F32; one workgroup per head first, split over key blocks if
    the profile asks.
  - `embed`: `x = token_embd[id] + pos_emb[pos]` from Q8_0, id and position as immediates.
  - `pack_f16`: F32 rows into an F16 cache.
- `src/whisper/`:
  - `mod.rs`: metadata and shapes checked once at load, special ids, `transcribe` (the seek
    loop), tokens and text.
  - `frontend.rs`: the reference frontend ported exactly (research's FFT 400 with explicit
    `mul_add`). The mel sums only the 4-bin groups that hold nonzero weights and frames that see
    only padding take the value of a silent frame, computed once; both exact (zeros add exact
    zeros). Frames go to four scoped threads.
  - `encoder.rs`: conv stem, the pre-LN blocks (the plain transformer block lives here until a
    second family needs it), cross K/V for every decoder layer.
  - `decoder.rs`: the GPU step, KV caches, logits readback.
  - `search.rs`: CPU side: suppression, timestamp rules, argmax and logprob, language,
    no-speech, `retrieve_segment`, the seek step. Scripted-logits unit tests.
  - `tokenizer.rs`: byte-level decode only.
- Not used by Whisper: `conformer.rs`, `spatial.wgsl`, `cpu.rs`.

### Encoder: one compute pass and one submit per window

mel [3000][128] → im2col → conv1 GEMM + GELU → [3000][1280] → im2col → [1500][3840] → conv2 GEMM,
GELU added onto `pos_emb` → 32 × (LN, `[q | k | v]` GEMM N = 3840, flash attention, out GEMM +
residual, LN, fc1 GEMM + GELU, fc2 GEMM + residual) → final LN → per decoder layer a `[K | V]`
GEMM (N = 2560, biases `[0 | b_v]`) and `pack_f16` into the cross cache. The SOT decoder step is
recorded into the same pass, so a window costs one submit and one 207 KB readback before decoding,
and the encoder output never leaves the GPU. Shapes are fixed (1500 frames, 448 positions), so
the arena is allocated once at load: x, y 7.7 MB each, `[q | k | v]` / im2col 23 MB, h 31 MB (also
conv1's output), cross cache 4 × 1500 × 2560 halves = 31 MB, self caches 4 × 448 × 2560 halves =
9 MB, logits 207 KB.

### Decoder: one GPU pass per token

Decision: the decoder runs on the GPU. Per token, turbo reads 97 MB of decoder weights (Q8_0),
70 MB of tied head and 31 MB of F16 cross K/V: ~200 MB, memory-bound at the M2's ~100 GB/s on
either processor (≥ 2 ms). Our CPU matvecs reached ~47 GB/s (`docs/perf.md`, the F32 LSTM), so
the CPU would take ≥ 4 ms per token plus a 61 MB readback of cross K/V per window, and large-v3's 32
decoder layers (~800 MB per token) rule the CPU out. The CPU keeps the logit filters over 51 866
floats.

A step is one compute pass of ~55 dispatches: `embed`; per layer LN, gemv `[q | k | v]`,
`pack_f16` of k and v into the self cache row, `decode_attention` over pos + 1 keys, gemv out +
residual, LN, gemv cross q, `decode_attention` over 1500 keys, gemv out + residual, LN, gemv fc1
+ GELU, gemv fc2 + residual; final LN, gemv head (51 866 rows), copy for readback. The buffers are
the same every step, so the bind groups are cached and token id, position and key count go in
immediates: a step only re-records its dispatches. SOT runs with the encoder; `<|lang|>` and
`<|transcribe|>` go into one pass that reads back only the last logits; then one pass and one
readback per generated token, as the reference's step graph does (`decoder.h:105-128`).

Decision point after the correct slice, with per-token GPU time and submit/readback overhead
measured: keep this, or move suppression, timestamp rules, argmax and logprob into a GPU kernel
(a few bytes of readback) and record several steps per submit, stopping at EOT.

### Decoding, long audio and `max_audio_ms`

- `search.rs` ports the reference default above: language detection, the no-speech
  probability, suppression order, timestamp rules, greedy argmax with the f64 logprob, the 256 /
  448 caps, `retrieve_segment` and the seek step, with comments naming `model.cpp`.
- No temperature fallback (decision 1): T = 0 always, plus the no-speech skip, which needs only
  avg_logprob and `no_speech_prob`. Windows where the reference falls back are random there and
  cannot be matched; fixtures avoid them.
- The library runs the seek loop for every input, as the reference: `transcribe` takes any
  length, and `max_audio_ms()` returns `Some(30_000)` (decision 4). The CLI is unchanged: it
  splits long audio at pauses into pieces of at most 30 s; `--segment 0` gives the reference's
  single pass over the whole file.
- Language is auto-detected and the task is transcribe; no new public API (decision 3).

### Tokens, text and fixtures (decision 2)

- `Transcript.text` = the reference's text.
- `tokens` = the text tokens of the reference's segments in order, `start_ms` = their segment's
  start. `piece` = the text the token completes: a character split over byte-level tokens goes
  to the token with its last byte, so pieces are valid UTF-8 (some empty) and concatenate to the
  segment text. Timestamp and special tokens are not tokens; an unfinished tail is only in the
  text. `Token`'s doc and `readme.md` say so.
- `make fixtures ... TIMESTAMPS=segment`: the recipe passes `--timestamps $(TIMESTAMPS)` (default
  `token`) and the awk keeps a `segments:` block as it keeps a `tokens:` one.
- `tests/models.rs` reads `segments: N` and `[t0 -> t1] text`: the text must match exactly, and
  the tokens grouped by `start_ms` must reproduce each segment's start and text. t1 is not in the
  API, so it is not checked.

## Lessons from research

The `research` branch (`docs/plans/20261008-whisper-tiny-turbo.md`, stopped by the user on
2026-10-09) ported Tiny and turbo against a custom single-thread CPU F32 build of the reference
with tensor tolerance gates. On the M2, turbo warm was 16.4 s on `jfk` vs 1.46 s (11.2× slower)
and 21.6 s vs 1.73 s on a 30 s clip; Tiny 5.2–7.3× slower; turbo load 2.3–3.4 s, footprint
22.7 GB, 9 GB after waiting every 4 blocks (`research:BENCHMARK.md:430-478`). Why:

- All weights expanded to F32 and repacked at load: 3.24 GB on the GPU for an 0.89 GB file.
- Compensated GEMM, LayerNorm and erf to meet the CPU-F32 tolerances: 1.5–2× slower.
- A new output buffer, uniform buffer, bind group and three error scopes per op; a submit per op
  or per block.
- The self K/V copied into a new buffer every step; full-vocab logits for every prompt row;
  materialized encoder attention (2 × 180 MB); 32-row GEMM tiles for one-row projections (the head
  16.6 → 8.6 ms with a matvec). After fixes the first-call encoder was still 3.1 s, the decoder
  0.62 s.

Worth keeping: the FFT 400 and mel ported with explicit `mul_add`; the byte-level decode
(`research:src/whisper/tokenizer.rs`); the timestamp rules and segment retrieval
(`research:src/whisper/timestamps.rs`) and the seek core (`long.rs`) as cross-checks for the port;
its edge cases (`research:tests/fixtures/whisper-policy.json`, `whisper-segments-*.json`) as
inspiration for the scripted-logits tests. Its native-Metal comparison matched text, segments,
language and no-speech on `jfk` and a 30 s clip despite F16 KV and flash attention, so exact text
fixtures don't need bit-exact arithmetic. Without fallback, turbo ended `whole-earth` in repeated
"Thank you.", repeated "Don't settle." in `love-loss` and gave "you" on digital silence
(`research:VALIDATION.md:249`), relevant to decision 1.
Avoid: F32 expansion, compensated arithmetic, per-op allocation and error scopes, tolerance
oracles and receipts, a separate `wavo::whisper` API, `rayon`.

## Line budget

Non-test lines today: the shared core 2.13k (`gguf.rs` 259, `gpu/mod.rs` 584, kernels 1005
without `spatial.wgsl`, `cpu.rs` 189, `lib.rs` + `error.rs` 96); `conformer.rs` 244 and
`spatial.wgsl` 118 serve only the Conformer families. Whisper uses ~1.94k of the core, adds ~0.3k
to it (gemv, decode attention, embed, pack, GELU, im2col params) and ~0.75k in `src/whisper/`:
~3.0k. To stay there: portable kernels only unless a fast one measures clearly faster; no
fallback, beam search, word timestamps, translation, language hint or `.en` prompt; the
transformer block stays in `src/whisper/`. If core + Whisper passes ~3.1k at the end of the
correct slice, simplify before speed work.

## Decisions for the user

1. Temperature fallback: leave it out (recommended: deterministic, small; output differs from
   the reference only on windows where the reference itself is random), or port it with our own
   seeded RNG and a deflate for the compression ratio (a dependency such as `miniz_oxide`, or
   ~150 lines).
2. Tokens and fixtures: segment start times on tokens and fixtures that hold segments, no API
   change (recommended), or segments with end times in the public API.
3. Language and task: auto-detect and transcribe only (recommended now); a language hint or
   translate is a later API change.
4. `max_audio_ms()`: `Some(30_000)`, so the CLI splits into single windows; the library keeps
   the seek loop for any length.
5. CLI short name `whisper-turbo`.
